What the app is

A class scheduler. A class rep creates a class and gets a six-character code. Classmates join with the code. When the rep adds a quiz, midterm, final or other item, a piece is carved out of the class block, and every window that has joined the class shows it.

There is no server. Classes are stored in the browser (localStorage), and each window keeps its own private note (sessionStorage) about which classes it created or joined. That is how two windows on one computer can play rep and student.

A route through the code (reference, 3 stops)

Stop 1: the entry point. In js/forms.js, search for Forms.wireItemForm. Its submit handler reads the form, calls Store.addItem(...), then Forms.onChange(...) to redraw this window.

Stop 2: the storage and the sharing. In js/store.js, search for Store.addItem (it saves the item inside its class) and for addEventListener('storage' (the browser fires this in the other window, which then calls Store.notify and redraws).

Stop 3: the kernel. In js/carve.js, search for Carve.fit. It tries sizes until the shape covers the target fraction of the block (midterm 1/3, final 1/2, quiz 20–50% from the slider), growing from the bottom-right corner. js/week-view.js (WeekView.render) cuts that shape out of the block with an SVG mask.

Where things are

The folder, in plain words
  • index.html: the one page. It only holds the empty frame and loads the scripts in order.
  • css/: base.css (layout and parts), effects.css (the stone look), and the stone textures.
  • js/: one file per job. store.js data, time.js days and dates, carve.js the carve, week-view.js and day-view.js the two views, forms.js the dialogs, background.js the background, app.js ties it together.
  • test/carve-test.html: a check page for the carve areas.
  • devpost/: the planning documents.

Each script is loaded with a plain script tag in a set order (see the bottom of index.html), so a file can use the ones before it.

A practice to reuse

Check the number, then look at it with the person it is for. The carve had a measurable rule (midterm one third, final one half). test/carve-test.html proved the areas were right, and it kept passing while the carve was redesigned twice. What changed the design was trying it: the shape floated in the middle and covered the course title, so the rule moved to “fill from the bottom-right corner”. Next time, write the rule so it can be measured, and put it in front of the user while it is still cheap to change.

Run it again

Double-click open-demo.bat (opens two Chrome windows), or open index.html in Chrome and press Ctrl+N for a second window. Create a class in one, join it in the other, then add a quiz.
